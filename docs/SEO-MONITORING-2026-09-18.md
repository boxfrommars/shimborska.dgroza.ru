## Охват каждого среза

### Трафик и запросы

- По каждому поисковику: показы, клики, CTR и средняя позиция всего сайта.
- Главная: те же показатели отдельной строкой.
- Десять страниц-лидеров определяются отдельно в каждом поисковике по кликам
  за текущие 28 полных дней. При равенстве — по показам по убыванию, затем
  по URL по возрастанию. Если строк меньше десяти, сохранять доступные.
  Главная учитывается в рейтинге, но её показатели повторно не дублируются.
- Для выбранных лидеров собирать показатели во всех четырёх окнах сравнения.
  Состав URL внутри одного среза фиксирован. Отмечать вошедшие и выбывшие
  страницы относительно предыдущего среза этого поисковика. Выход из топ-10
  сам по себе не означает потери трафика или исключения из индекса.
- Десять ведущих запросов выбирать по кликам за текущие 28 дней; при равенстве
  — по показам, затем по тексту. Собрать их показатели за те же четыре окна.
  Точные запросы `шимборская стихи` и `вислава шимборская стихи` фиксировать
  отдельными строками независимо от попадания в топ-10, без повторов.
  Не заменять один запрос другим и не объединять их показатели.

Если URL-разрез или иной показатель недоступен, записать ограничение именно
этого источника; не выбирать за него лидеров другого поисковика.

### Индексирование и техническое состояние

- Сводка каждого кабинета: число проиндексированных и исключённых URL,
  причины исключения, ошибки обхода, сообщения о санкциях, безопасности
  и новых технических проблемах. Сохранять дату обновления этих отчётов.
- Главная и текущие лидеры: статус индексирования и последняя дата обхода
  в соответствующем поисковике; для главной также выбранный поисковиком
  canonical. Сохранять формулировку статуса и часовой пояс времени, если он
  указан. Не смешивать дату просмотра отчёта, обхода и индексирования.
- Sitemap: публичный HTTP-ответ, число URL, а в каждом кабинете — статус,
  дата чтения, количество обнаруженных URL и новые ошибки. Публичный список
  URL брать из текущего sitemap, без постоянной привязки к прежним 96 URL.
  Старую заявку Google `/sitemap.xml` с ошибкой учитывать в контексте успешной
  `/sitemap.xml?t=1`; её прежнее состояние само по себе не новая проблема.
- В публичном HTML главной и объединённого списка лидеров проверить HTTP,
  цепочку редиректов и конечный URL, canonical, meta robots и X-Robots-Tag;
  сверить доступность путей в `robots.txt`. Один URL достаточно загрузить один
  раз за запуск. Учесть предусмотренные приложением перенаправления.
- Отсутствие description на стихотворениях соответствует решению владельца.
  Предупреждение кабинета об этом не считать регрессией. Различать старый
  индексированный HTML и фактический production; локальный Git сам по себе
  не подтверждает публикацию изменений.
- Рост каталога, подтверждённые релизы и задержки отчётов записывать как
  контекст. Отложенное индексирование новых URL отличать от потери ранее
  индексировавшейся главной или страницы-лидера.

### Представление главной в Google

Раз в неделю проверять обычную выдачу по точному тексту `шимборская стихи`
без кавычек, автора и `site:`. Для результата главной записывать название сайта
над заголовком и фактический сниппет. Фиксировать дату, поисковик и доступные
условия поиска; настройки региона и персонализации не менять.

Если главная не найдена на первой просмотренной странице либо выдача закрыта
CAPTCHA, записать пробел. Ручную позицию не использовать как метрику и не делать
вывод об исключении из индекса. Выбор Google названия сайта может отличаться
от заявленного в разметке; сам по себе такой выбор не техническая регрессия.

## Периоды и правила расчёта

Использовать обычный Web-поиск с одинаковыми фильтрами в сравниваемых окнах:
все страны и устройства, без фильтра запроса или URL для сводки сайта.
Не смешивать Web с отдельными отчётами Images, News, Discover или Chat.
Если кабинет не позволяет отделить нужный тип трафика, явно обозначить состав
источника и ограничение сопоставимости.

Для каждого источника определить последний полный день с созревшими данными.
Выбрать общий конечный день `E`. Если кабинет недоступен или отстаёт более
чем на семь календарных дней от самого свежего доступного источника, остальные
проверять по своему общему `E`, а отставший — за его доступные даты, с явной
пометкой. Не задерживать весь мониторинг из-за одного источника.

| Окно | Даты, включительно | С чем сравнивать |
| --- | --- | --- |
| Текущие 7 дней | `E − 6` … `E` | Предыдущие 7 дней |
| Предыдущие 7 дней | `E − 13` … `E − 7` | — |
| Текущие 28 дней | `E − 27` … `E` | Предыдущие 28 дней |
| Предыдущие 28 дней | `E − 55` … `E − 28` | — |

Записывать фактические даты, фильтры, источник, дату свежести и часовой пояс
отчёта, если он известен. Одинаковые календарные даты кабинетов не обязательно
означают одинаковые границы суток. Динамику оценивать внутри поисковика;
показатели Google, Bing и Яндекса не суммировать.

- CTR = клики / показы × 100%; при нуле показов CTR не определён. Разницу CTR
  показывать в процентных пунктах, без усреднения построчных процентов.
- Среднюю позицию брать из отчёта нужного уровня и периода. Не заменять её
  средней позицией клика, ручной выдачей или средним по видимым строкам.
  Положительная разница «текущее − предыдущее» означает численное ухудшение.
- Для показов и кликов приводить абсолютные значения, абсолютную разницу
  и процент изменения, если прежнее значение больше нуля.
- `н/д` означает недоступные сведения; рядом записывать причину. Ноль
  допустим при явном нулевом значении источника. Отсутствие строки, скрытые
  малочастотные запросы и неполный список не доказывают нулевой трафик.
- Сводные показатели брать из сводки, а не суммы топ-10. Обрезанную таблицу
  не выдавать за полный отчёт. Невозможность выбрать точное окно фиксировать,
  не заменяя его периодом другой длины.
- При малом числе показов или кликов описывать наблюдение без утверждений
  о доказанном SEO-эффекте. Рост с одного клика до двух и снижение с двух
  до одного не доказывают устойчивого тренда. Меняющийся состав запросов,
  новые страницы и сезонность учитывать при интерпретации средней позиции.

## Доступ и границы автоматизации

Для локального запуска нужны включённый компьютер, запущенное приложение
Codex, доступный Chrome с авторизованными кабинетами и разрешение на запись
этого журнала. При недоступности источника, CAPTCHA или ограничении записи
сообщить точный пробел в недельном отчёте и продолжить доступные проверки.
Защитные проверки не обходить и разрешения автоматически не менять.

Автоматизация может изменять только этот Markdown-файл. Не коммитить, не
выполнять push, deploy, генерацию sitemap, исправление кода, метатегов или
контента, повторные заявки на обход либо изменения настроек поисковиков.
При подтверждённой проблеме рекомендовать действие владельцу, не выполнять
откат самостоятельно. Завершение старого пилота не завершает этот мониторинг.

В журнале не сохранять аккаунты, адреса электронной почты, cookies, токены,
секреты, персональные данные и закрытые ссылки кабинетов. Достаточно названия
отчёта, публичного URL, дат, фильтров и наблюдаемых значений.

Яндекса, месячный CTR главной Google и сохранение индексирования лидеров;
при доступности уточнить причину Excluded изображений и canonical главной
Bing. Публичный HTTP-контроль остаётся незавершённым из-за описанного
ограничения выполнения. Подтверждённых новых production-релизов или
роста каталога в ходе проверки нет; неизменные 96 URL sitemap не
доказывают неизменность содержимого страниц. Изменён только локальный
журнал, без коммита и push.

### 16 октября 2026 года — завершение публичного HTTP-контроля

После сверки явного требования публичных HTTP-проверок в строках 65–73
этого протокола автоматический контроль разрешил повторный read-only
запрос. Указанный в предыдущем дополнении пробел **публичного HTTP** закрыт;
первоначальное отклонение и порядок его разрешения сохранены в истории.
Поисковые live-тесты и переобход не запускались.

Одним проходом проверены 19 HTML-адресов из объединения текущих лидеров
Google, Bing и Яндекса (включая главную и отдельную параметризованную
страницу «Кота»), а также `robots.txt` и `sitemap.xml` — всего 21 адрес.
HTTP-клиент не следовал редиректам автоматически, поэтому исходный ответ
200 и отсутствие Location подтверждают отсутствие перенаправления.

| Объект | Подтверждённый результат |
| --- | --- |
| Все 19 HTML-адресов | HTTP 200, без Location, ровно один ожидаемый title, без meta robots и X-Robots-Tag. |
| 18 HTML-адресов без параметров | Единственный self-canonical. |
| `/different/cat-in-empty-apartment?ysclid=…` | HTTP 200; единственный canonical указывает на чистый `/different/cat-in-empty-apartment`, как и ожидается для этого параметра. |
| Главная | Один description; остальные 18 проверенных HTML-адресов — без description, согласно решению проекта. |
| `/robots.txt` | HTTP 200 без редиректа; `User-agent: *`, `Allow: /`, ссылка на текущий sitemap. Проверенные пути не запрещены. |
| `/sitemap.xml` | HTTP 200 без редиректа; XML содержит 96 URL, все 96 уникальны. |

Таким образом, в текущем production HTML главной и всех выбранных лидеров
техническая регрессия не подтверждена. Пробелы в кабинетах остаются:
запаздывающие инструменты Яндекса, Web-only сводка Bing, точная причина
Excluded у трёх изображений и выбранный Bing canonical главной.
Дополнительная карточка Bing по-прежнему не открывалась после отдельного
отклонения автоматическим контролем. Для владельца срочных действий по
полученным данным не требуется; продолжать недельное наблюдение.

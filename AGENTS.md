# shimborska.dgroza.ru

Постоянные правила работы с репозиторием сайта Виславы Шимборской.

## Документация

- `readme.md` — запуск, команды и карта документации.
- `docs/CONTENT.md` — каталог, шаблоны и правила изменения произведений.
- `docs/FRONTEND.md` — Blade, CSS, JavaScript, accessibility и ручные проверки.
- `DEPLOYMENT.md` — переносимые production-требования приложения.

Перед изменением соответствующей области прочитать её документ. Подробности не
дублировать в этом файле.

## Границы проекта

- Runtime: PHP `^8.3`, Laravel `^13`; базы данных и frontend-сборки нет.
- Сайт контентный и read-only. Не добавлять пользовательское или постоянное
  состояние, миграции либо команды, изменяющие пользовательские данные.
- Сохранять публичные URL, имена маршрутов, тексты, кодировку и визуальный стиль,
  если пользователь прямо не попросил обратного.
- Frontend остаётся на Blade, CSS и vanilla JS. Не добавлять npm, Vite, jQuery,
  UI-фреймворки или новые архитектурные слои без явной необходимости.
- Не помещать в Git секреты, production `.env`, ключи или сертификаты.

## Контент и маршруты

- `resources/data/poems.php` — единственный источник структуры каталога
  произведений и их порядка.
- Каждой записи каталога должен соответствовать ровно один шаблон
  `resources/views/poems/{section}/{slug}.blade.php`.
- Поиск произведения выполняется по точной паре `section + slug`; неизвестные и
  несовпадающие адреса должны возвращать `404`.
- Внутренние ссылки строить через именованные маршруты `main`, `project`,
  `author`, `poem` и `section`.
- При переносе произведения сохранять `slug` и добавлять постоянный redirect со
  старого публичного URL.
- Изменять произведения только по правилам `docs/CONTENT.md`; не править
  механически орфографию, пунктуацию, переводы, оригиналы или связанную разметку.

## Проверки и зависимости

- Команды запуска и автоматических проверок брать из `readme.md`.
- После изменений маршрутов, каталога, Blade, CSS или JavaScript выполнять
  подходящие автоматические и ручные сценарии из `docs/FRONTEND.md`.
- Если изменение делает неточным утверждение в `readme.md`, `docs/CONTENT.md`,
  `docs/FRONTEND.md` или `DEPLOYMENT.md`, обновлять соответствующий документ в
  рамках той же задачи.
- Задача завершена только тогда, когда код, тесты и документация согласованы.
- При изменении зависимостей согласованно обновлять `composer.json` и
  `composer.lock`; lock-файл вручную не редактировать.
- Сохранять чужие незакоммиченные изменения и проверять diff перед коммитом.

## Deployment и Git

- При изменении runtime, зависимостей, application-команд, env-интерфейса,
  публичного каталога, writable-путей, маршрутов, health endpoint, lifecycle
  hooks, sitemap или rollback обновлять `DEPLOYMENT.md`.
- Обычный релиз контента или исправление кода не требует изменения deployment-
  контракта, если требования приложения не поменялись.
- Не добавлять в `DEPLOYMENT.md` инфраструктурные детали конкретного сервера.
- Не выполнять push, merge или production-деплой без явного запроса.
- Не применять destructive Git-команды и не запускать миграции.
